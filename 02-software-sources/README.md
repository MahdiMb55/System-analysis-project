# خاستگاه‌های نرم‌افزار

پروژه DASS — تحلیل دانشگاهی

## ۲-۱. نقش تحلیلگر و تأمین نرم‌افزار
تحلیلگر میان خرید، ساخت و یکپارچه‌سازی تصمیم می‌گیرد. هدف DASS حفظ مالکیت منطق نوبت‌دهی و کاهش هزینه اجزای عمومی است.

## ۲-۲. برون‌سپاری
برون‌سپاری پیامک و پرداخت به متخصصان، هزینه زیرساخت را کاهش می‌دهد ولی وابستگی فروشنده و ریسک قطعی دارد. Nearshoring و Offshoring برای توسعه کامل به دلیل نیاز به تعامل، زبان و قواعد محلی گزینه‌های فرعی‌اند. قرارداد SLA و امکان خروج داده ضروری است.

## ۲-۳. شش منبع
| منبع | کاربرد و ارزیابی |
|---|---|
| IT Services Firms | توسعه سفارشی؛ هزینه و وابستگی قراردادی |
| COTS | ابزار رزرو آماده؛ بررسی محدودیت فرم و ظرفیت |
| ERP | امکانات گسترده اما پیچیدگی نامتناسب |
| SaaS | پیامک و پرداخت یا سامانه رزرو آماده؛ هزینه تکراری |
| OSS | اجزای عمومی با بررسی مجوز و امنیت |
| In-house | مالکیت موتور پویا و کنترل سفارشی‌سازی |

امتیاز ۱ ضعیف تا ۵ عالی؛ وزن و امتیازها فرضی‌اند و حاصل آزمون بازار نیستند. امتیاز نهایی مجموع وزن ضربدر امتیاز است.

## ۲-۵. RFP/RFQ و اعتبارسنجی
نمونه RFP: ارائه‌دهنده باید API، SLA، حفاظت داده، محیط آزمایشی، شرایط خروج و سازوکار خطا را توضیح دهد. RFQ: قیمت هر پیامک، هزینه ثابت، هزینه راه‌اندازی، کارمزد و مالیات را جدا کند. Benchmark پیشنهادی: صد درخواست رزرو هم‌زمان، صحت عدم تداخل و زمان پاسخ؛ برای پیامک نرخ تحویل و تأخیر، برای پرداخت تکرار اعلان و تطبیق تراکنش. هیچ آزمونی اجرا نشده است. بررسی منابع مستقل و مشتریان مرجع نیز پیش از قرارداد لازم است.

## ۲-۶. بازکاربرد نرم‌افزار
بازکاربرد موردی (Ad Hoc) بدون برنامه، تسهیل‌شده (Facilitated) با ابزار مشترک، مدیریت‌شده (Managed) با کنترل سازمانی و طراحی‌شده (Designed) با اجزای از ابتدا قابل استفاده مجدد است. راهبرد Designed برای اجزای قابل استفاده مجدد مانند قواعد زمان‌بندی، اعتبارسنجی فرم، رابط پرداخت و پیامک پیشنهاد می‌شود. مجوز و امنیت اجزای OSS باید بازبینی شود.

## ۲-۷. نتیجه
موتور نوبت‌دهی اختصاصی، اجزای عمومی متن‌باز و خدمات بیرونی پرداخت و پیامک؛ بدون انتخاب قطعی فروشنده یا پیاده‌سازی.
